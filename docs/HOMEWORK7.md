## 1. PWA Manifest & Installation

- [x] M1. Валидный `manifest.json` с `name`, `short_name`, `start_url`, `scope`, `display: "standalone"`, `theme_color`, `background_color`. — `public/manifest.webmanifest`; `start_url` и `scope` — `"./"`, потому что `base: './'` должен работать и в подпапке.
- [x] M2. Иконки 192×192 и 512×512. — `public/icons/icon-192.png`, `icon-512.png`, плюс `icon-maskable-512.png` (maskable) и `apple-touch-icon-180.png`; все генерируются из `public/icons/icon.svg`.
- [x] M3. Манифест подключён в `index.html`. — `<link rel="manifest" href="./manifest.webmanifest">` + apple-метатеги (iOS не ставит приложение по манифесту).
- [x] M4. Приложение устанавливается в поддерживаемых браузерах. — проверено в Chromium на production-сборке: манифест валиден, иконки грузятся, SW с обработчиком `fetch` контролирует страницу.

## 2. Service Worker Lifecycle

- [x] S1. Обработка `install`, `activate`, `fetch`. — `src/sw/sw.js`.
- [x] S2. Pre-cache оболочки: собранные JS/CSS, иконки, offline-страница. — `cache.addAll` в `install`; список файлов подставляет `plugins/vite-plugin-service-worker.js` на этапе `generateBundle`, когда хеши уже известны. Пути относительные — иначе сборка ломается в подпапке.
- [x] S3. Версионирование кэшей и удаление устаревших при активации. — `fleetdesk-precache-<version>`, где `version` = версия `package.json` + sha256 списка файлов; в `activate` удаляются все `fleetdesk-*`, которых нет в `KEEP`.
- [x] S4. Механизм обновления: уведомление о новой версии + кнопка активации. — `src/pwa/registerSW.js` (`updatefound` → `statechange`) → `src/pwa/swUpdateStore.js` → `src/components/UpdateToast.jsx`; кнопка шлёт `SKIP_WAITING`, после `controllerchange` страница перезагружается ровно один раз.
- [x] S5. Обновление применяется без ручной очистки storage. — `skipWaiting()` не вызывается в `install`; при активации удаляется только старый precache, а `fleetdesk-api-v1` и `fleetdesk-assets-v1` переживают деплой (иначе каждое обновление стирало бы офлайн-данные). Проверено сценарием «сборка → тост → Update now → новая версия».
- [x] S6. Workbox или рукописный SW. — рукописный, без зависимостей.

Дополнительно: одинаковая пересборка даёт байт-в-байт тот же `sw.js` (версия — хеш списка файлов), поэтому ложных «доступно обновление» не бывает. В dev-режиме SW отключён, а `/sw.js` отдаёт воркер, который удаляет сам себя (`plugins/vite-plugin-sw-dev-killer.js`).

## 3. Runtime Caching

- [x] C1. Минимум две стратегии. — **cache-first** для статики (скрипты, стили, изображения, иконки, шрифты) и **stale-while-revalidate** для публичного API (`api/fleet.json` — список, `api/vehicles/<id>.json` — детали).
- [x] C2. Ранее загруженные данные API доступны офлайн. — `fleetdesk-api-v1` не версионируется по сборке; при отсутствии сети SWR отдаёт сохранённую копию. Машина, файл которой не запрашивался, берётся из закэшированного каталога (`getVehicle` → fallback в `src/api/vehiclesApi.js`).
- [x] C3. Пользователю видно, что данные из кэша. — SW добавляет заголовки `X-Served-From` и `X-Cached-At`; `src/api/http.js` их читает → `src/services/cacheStatusStore.js` → `useCacheStatus` → пометка «· saved copy at 14:32» в списке и баннер `CachedDataBanner` (показывается офлайн или если копии больше 5 минут).
- [x] C4. Ограничение роста кэша. — `trimCache` после каждой записи (80 записей API, 60 ассетов, FIFO по `cache.keys()`) и `sweepExpired` по возрасту (7 и 30 дней) при активации и по сообщению `SWEEP_CACHES`.
- [x] C5. Не кэшировать аутентификацию, токены и приватные данные. — правило 3 в `fetch`: хосты `googleapis.com`, `firebaseapp.com`, `firebaseio.com`, `gstatic.com`, `google.com` возвращаются без `respondWith` (это также сохраняет credentials и popup Google-входа); плюс правило 1 — любые не-GET запросы вообще не трогаются.
- [x] C6. Сбойные запросы не ломают приложение. — при отсутствии сети и кэша SW отдаёт JSON `503` с `X-Served-From: none`, `http.js` превращает его в `ApiError({ offline: true })`, а UI показывает сообщение с кнопкой повтора.

## 4. Offline Page

- [x] O1. Отдельная страница `/offline`. — маршрут `#/offline` (`src/pages/OfflinePage.jsx`) + автономный `public/offline.html` для навигации, которую SW не может обслужить оболочкой.
- [x] O2. Осмысленное сообщение и оформление. — объяснение + список того, что работает офлайн; `offline.html` не зависит от бандла (инлайновые стили), поэтому работает даже без precache.
- [x] O3. Кнопка Retry Connection. — в обеих версиях; в приложении она запускает реальную проверку и возвращает на предыдущую страницу при успехе.
- [x] O4. Индикатор online/offline. — `src/components/ConnectionStatus.jsx` в шапке; офлайн превращается в ссылку на `#/offline`.
- [x] O5. Если навигацию нельзя выполнить офлайн — показывается offline-страница. — правило 6 в `fetch`: оболочка из precache, иначе `offline.html`.
- [x] O6. Ранее посещённые страницы и закэшированные публичные данные доступны офлайн. — оболочка и все чанки (включая ленивые) в precache; каталог в API-кэше. Проверено: офлайн-перезагрузка показывает список, а `#/about` и `#/dashboard` открываются, даже если до этого не открывались.
- [x] O7. При возврате сети всё работает как обычно. — `ConnectivityProvider` при переходе offline → online делает `invalidateQueries`, а SWR обновляет кэш в фоне.
- [x] O8. Offline-страница работает без интернета; `navigator.onLine` недостаточно. — `src/services/connectivityService.js`: `navigator.onLine === false` считается надёжным негативом, положительный ответ доказывается запросом `ping.txt` (`no-store`, таймаут 3 с), плюс сигналы из реального трафика приложения; backoff 5→60 с только в офлайне. На этот же источник переведён `onlineManager` TanStack Query.

## 5. Mobile

- [x] B1. Приложение адаптировано для мобильных. — mobile-first CSS, проверено на 320 / 360 / 390 / 414 / 768 px.
- [x] B2. Поддержка экранов от 320 px. — проверено автоматически: `scrollWidth === clientWidth === 320`.
- [x] B3. Адаптивное меню навигации. — бургер ниже 768 px (`src/components/AppLayout.jsx`, `src/styles/layout.css`): `aria-expanded`/`aria-controls`, фокус в панель, Esc закрывает и возвращает фокус, подложка закрывает по тапу, переход по ссылке закрывает.
- [x] B4. Карточки, формы, таблицы, дашборд и детали подстроены под узкие экраны. — сетка карточек `minmax(min(100%, 280px), 1fr)`, форма в одну колонку до 640 px, дашборд `auto-fit`, детали в одну колонку до 960 px. Таблиц в приложении нет — данные выводятся списками `dl`.
- [x] B5. Нет горизонтальной прокрутки и наложений. — шапка переносится вместо переполнения, `min-width: 0` на текстовых блоках, проверка `scrollWidth` в портрете и в альбоме.
- [x] B6. Кнопки и контролы удобны для пальца. — токен `--control-height: 44px` (40 px только при `pointer: fine`) применён к кнопкам, полям, селектам, чипам, пагинации и ссылкам навигации; автоматическая проверка «нет целей ниже 44 px» проходит.
- [x] B7. Единые отступы, типографика и иерархия. — всё из `src/styles/tokens.css`, новых «магических» значений не добавлялось.
- [x] B8. Портрет и альбом. — проверено 320×640 и 740×360; `100svh` вместо `100vh`, чтобы не прыгала высота.
- [x] B9. Мобильная версия полностью функциональна. — поиск, фильтры, сортировка, пагинация, форма добавления, смена статуса и удаление работают на узком экране.
